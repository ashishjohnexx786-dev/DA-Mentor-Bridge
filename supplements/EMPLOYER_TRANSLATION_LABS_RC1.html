Databricks employer-translation lab

Your core Spark + Delta + Medallion knowledge already does the hard conceptual work. This lab teaches the workspace names and workflow employers often mention.

1. Open a free learning environment.
Databricks Free Edition — official signup guide. Read the limitations first; use the no-cost environment only.
2. Workspace + notebook orientation.
Official getting-started tutorials. Create/open a notebook, identify workspace objects, run a tiny SQL/Python cell, and locate Unity Catalog concepts.
3. PySpark translation.
Official DataFrame tutorial. Load a small CSV/Parquet dataset, select/filter, aggregate, join, inspect schema and explain what is identical to local PySpark.
4. Delta translation.
Create a Delta table; verify schema, overwrite/append behavior, and one version/history/time-travel operation available in your environment. Reuse concepts from Stage 13 rather than relearning them.
5. Bronze → Silver → Gold.
Take one small raw dataset through three layers. Bronze preserves source shape, Silver fixes types/quality/deduplication, Gold produces one business-ready aggregate.
6. Incremental/reliable pipeline.
Official ETL quick-start. Build or adapt an incremental flow. Where your free environment supports it, schedule a notebook/job or inspect the equivalent workflow UI.
7. Failure + recovery proof.
Intentionally introduce one bad schema/value/path. Capture the failure, identify the cause, repair it, rerun safely and record why the result is trustworthy.

Completion evidence

  • Notebook/code exported or committed to GitHub.
  • Bronze/Silver/Gold table or folder evidence.
  • One PySpark join/aggregation you can rewrite without looking.
  • One Delta version/time-travel or incremental-load proof.
  • One failure → diagnosis → repair note.
  • 90-second explanation: “How my existing Spark/Delta knowledge maps to Databricks.”

This is deliberately a translation lab, not a second Databricks course.

Snowflake warehouse translation lab

Activate this only when several target jobs mention Snowflake. The goal is platform familiarity, not another full specialization.

1. Use an official trial only if you choose this pack.
Snowflake official getting-started tutorials.
2. Translate warehouse concepts.
Create/inspect a database, schema, table/view and virtual warehouse. Write down the equivalent concepts you already know from PostgreSQL/Fabric.
3. Load data.
Use an official COPY/loading tutorial with a small dataset; inspect file-format/stage concepts rather than memorizing UI clicks.
4. Reliability/security awareness.
Practice one role/privilege flow and inspect Time Travel. If cloning is available in your trial, demonstrate it once.

Completion evidence

  • SQL script for object creation + load + validation.
  • Screenshot/log of successful load and row-count reconciliation.
  • One RBAC note and one recovery/time-travel note.
  • 60-second comparison: Snowflake warehouse vs your Fabric/PostgreSQL mental model.

NoSQL / MongoDB awareness lab

Activate only when several target roles ask for MongoDB or NoSQL. The goal is to understand when a document model differs from the relational model you already know.

1. Learn the relational → document contrast.
MongoDB official: Intro to Non-Relational Databases.
2. Do one short official modeling unit.
MongoDB University: Data Modeling Intro — relationships, embedding vs referencing, scaling.

Proof

  • Model the same tiny entity set once relationally and once as documents.
  • Explain one case where embedding helps and one where it hurts.
  • Do not claim production MongoDB experience from this pack.
